# deberta-v3-xsmall-pii — v1

BIO token classifier for personally identifiable information (PII) in English text.

| | |
|---|---|
| Version | v1 (released as GitHub release `v1.0`, `deberta-v3-xsmall-pii.zip`) |
| Code | git commit `7b7549a` (training), `c1ef3c7` (faster inference) |
| Weights | `outputs/deberta-v3-xsmall-pii/` (best checkpoint = `checkpoint-5721`) |
| Base model | [`microsoft/deberta-v3-xsmall`](https://huggingface.co/microsoft/deberta-v3-xsmall) (~70M params incl. embeddings), fine-tuned from the original pretrained weights |
| Language | English only |
| Status | Superseded by v2 (see `v2.md`) |

## Labels

8 entity types, BIO-tagged → 17 labels (`O` + `B-`/`I-` per entity):
`PERSON`, `BUSINESS`, `ADDRESS`, `DOB`, `ACCOUNT`, `PHONE`, `EMAIL`, `TIN`.

## Datasets

| Source | Hugging Face ID | English docs available (train / eval split) | Eval split used |
|---|---|---|---|
| Nemotron | `nvidia/Nemotron-PII` | 100,000 / 100,000 | `test` |
| Gretel | `gretelai/synthetic_pii_finance_multilingual` | 25,948 / 2,962 | `test` |
| AI4Privacy | `ai4privacy/pii-masking-openpii-1.5m` | 163,740 / 40,909 | `validation` |

All three are synthetic. Only rows with language English were used.

### Label mapping (v1)
Source labels → our 8 entities; anything unlisted → `O`; `IGNORE` → masked from the loss.

| Entity | Nemotron | Gretel | AI4Privacy |
|---|---|---|---|
| PERSON | first_name, last_name | name, first_name | GIVENNAME, SURNAME |
| BUSINESS | company_name | company | – |
| ADDRESS | street_address, city, state, county, country, postcode, coordinate | street_address | STREET, BUILDINGNUM, CITY, ZIPCODE |
| DOB | date_of_birth | date_of_birth | – |
| ACCOUNT | account_number, customer_id, health_plan_beneficiary_number | bban, iban, credit_card_number, customer_id | CREDITCARDNUMBER |
| PHONE | phone_number | phone_number | TELEPHONENUM |
| EMAIL | email | email | EMAIL |
| TIN | ssn | ssn | TAXNUM, SOCIALNUM |
| IGNORE | – | – | DATE |

Known issues found later (fixed in v2): Gretel `last_name`, Nemotron `tax_id` and
`credit_debit_card` were unmapped and therefore trained as `O`.

### Processing
English filter → label map → overlapping spans: keep the longer → merge adjacent same-label spans
(addresses across commas/newlines, other labels across spaces) → seeded subsample (seed 42).

## Training configuration

| Setting | Value |
|---|---|
| Framework | Hugging Face `Trainer`; transformers 5.18.0, torch 2.8.0+cu128, datasets 5.0.1 |
| Recipe | OpenMed PII recipe: max length 384, first sub-token labelling, seqeval F1 |
| Max sequence length | 384 tokens; long docs split into sliding windows with 96-token overlap |
| Label all sub-tokens | No (continuation sub-tokens = -100) |
| Learning rate | 5e-5, linear decay, warmup ratio 0.1 |
| Epochs | 3 (5,721 steps; 60,999 train windows per epoch) |
| Batch size | 32 train / 64 eval, gradient accumulation 1 |
| Weight decay | 0.01 |
| Precision | fp32 weights + bf16 autocast |
| Eval / save | every 2,000 steps; keep best by validation seqeval F1 (`load_best_model_at_end`) |
| Seed | 42 |
| Hardware | NVIDIA GeForce RTX 5060 Ti 16 GB, Windows 11 |
| Training time | not recorded (log overwritten) |

Validation curve: F1 0.898 (epoch 1) → 0.921 (epoch 2) → 0.922 (epoch 3); eval loss
0.0234 → 0.0186 → 0.0171 — plateau, no overfitting.

## Limitations

- **Generalises poorly outside its training datasets.** The in-dataset test score above does
  not carry over to real financial documents.
- **DOB:** about 50% detected on real documents. 84% of training DOBs were `YYYY-MM-DD` and the
  cue "DOB" appeared only 15 times, so the model learned "ISO date after 'date of birth'".
- Never shown amounts, currencies or bank codes as negatives, so it can confuse them with
  account numbers.
- Misses entities in short, terse inputs; can clip boundaries on hyphenated IDs.
- Mostly US-style formats (e.g. TIN is mostly SSN `123-45-6789`); few Asian ID, company, address
  or phone formats.

# Multilingual PII token classifier — v5.4 (XLM-V base, span head with boundary smoothing)

v5.4 is **v5.2 with a different encoder**: [XLM-V base](https://huggingface.co/facebook/xlm-v-base). It has the
same 12-layer, 768-wide transformer as XLM-R base, but a **902k-token vocabulary** instead of 250k. The head is
v5.2's: a span head trained with boundary smoothing (ε = 0.1, distance 1 word; Zhu & Li, ACL 2022). The training
data (`ml_train_v5`), recipe (3 epochs, encoder LR 2e-5, head LR 1e-4, effective batch 32, seed 42), 8 labels and 12
languages are the same as v5.0–v5.2.

- **The large vocabulary splits text into fewer pieces:** about 13% fewer tokens than XLM-R on the same text
  (18% fewer for Japanese). So it is the fastest of the full-size v5 models on GPU, about level with v5.0 on CPU,
  and needs fewer 384-token windows per document.
- **Bigger download, same compute:** 778M parameters, of which 692M are the vocabulary's embedding table. A
  token only looks up its own row, so the work per token is the same as XLM-R base. The fp32 weights are 3.1 GB
  (v5.0–v5.2: 1.1 GB).
- Post-processing: punctuation trim on by default (`"trim_punct": true` in `config.json`).

**When to use it:** an alternative base-size model with accuracy level with v5.1 / v5.2 on the multilingual test
sets and slightly faster on long documents. **It is weaker on English** (English test 0.872 vs 0.906–0.907 for
v5.1 / v5.2), so prefer v5.1 or v5.2 for English-heavy text.

## Usage

The fp32 zip is 2.2 GB, over GitHub's 2 GiB limit per release file, so it is published as **two parts** that are
joined before unzipping. The parts are byte-for-byte pieces of one zip; the weights are the trained fp32 weights
(not quantised). Needs this repository's code at the `v5.1` tag or later (`src/heads.py`).

```bash
B=https://github.com/zackhng/pii-token-classifier/releases/download/v5.4
curl -L -O $B/xlmv-base-pii-ml-v5.4.zip.001 -O $B/xlmv-base-pii-ml-v5.4.zip.002
cat xlmv-base-pii-ml-v5.4.zip.001 xlmv-base-pii-ml-v5.4.zip.002 > model.zip      # Linux / macOS / Git Bash
# Windows cmd:  copy /b xlmv-base-pii-ml-v5.4.zip.001+xlmv-base-pii-ml-v5.4.zip.002 model.zip
sha256sum model.zip   # 3e1fa06ee0be09b1ceeac7026b7bc8cbc8164735a4eb41a8b7891b18a34f6f38
mkdir -p outputs/xlmv-base-pii-ml-v5.4 && unzip model.zip -d outputs/xlmv-base-pii-ml-v5.4
cd src && python predict.py --model_dir ../outputs/xlmv-base-pii-ml-v5.4 --text "Hi Tan Wei Ming (陈伟明), 已经 transfer SGD 25,000 到 account 123-456789-001"
# -> PERSON 'Tan Wei Ming', PERSON '陈伟明', ACCOUNT '123-456789-001'
```

## Limitations

- **English:** English test 0.872 vs 0.906–0.907 for v5.1 / v5.2 and 0.894 for v5.0.
- **Unseen structures:** the lowest of the released span models on `ml_struct_test` (0.942) and `ml_struct_dev` (0.927).
- **Training was resumed once:** the run crashed at step 36,000 of 45,411 (out of system memory while saving a
  checkpoint) and was resumed from the step-32,000 checkpoint with the optimizer, scheduler, data order and random
  state restored. The resumed run re-scored step 36,000 at the same validation macro-F1 as the crashed run (0.9503)
  and finished at 0.9516.
- **Single seed.** Differences of a few thousandths between the base-size models may not survive another seed.
- **Korean (Kiii²)** stays at about 0.85 strict for every model: its gold includes brackets that the trim removes
  (see the v5.0 card).
- Everything else in [`v5.md`](v5.md)'s Limitations applies unchanged: synthetic evaluation apart from Kiii², and
  non-commercial training sources.

## Reproduce

```bash
cd src
python train.py --config train_ml.yaml --train_split ml_train_v5 --val_split ml_val_v5 \
  --output_dir outputs/pii-ml-XLMV-BS-v5data --model_name facebook/xlm-v-base \
  --batch_size 8 --grad_accum 4 --grad_ckpt \
  --head span --head_lr 1e-4 --span_loss ce --bs_eps 0.1 --bs_d 1
# needs ~15.7 GB GPU memory (the optimizer state for the 902k-row embedding table);
# release folder: the trained model + "trim_punct": true in config.json
```

The other v5 experiments (other heads, extra layers, encoder swaps, adapters) are in the README's v5 experiment log.

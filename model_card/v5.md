# Multilingual PII token classifier — v5.0 (robust to unseen sentence structures)

The same 8 PII labels and 12 languages as v4: English, Simplified and Traditional Chinese, Japanese,
Korean, Hindi, Arabic, Thai, Vietnamese, Malay, Indonesian and Tagalog. The domain is **wealth
management**: KYC, source of wealth, RM notes, calls, e-mails, investment consultation, background
checks and periodic reviews.

|---|---|---|
| Model | XLM-R base, all 277.5M parameters fine-tuned | same |
| Recipe | v4.1's, unchanged | — |
| Training data | **`ml_train_v5`**: 450,144 documents (v4: 337k) | `ml_train` |
| What changed | **only the training data** (see [What changed](#what-changed-from-v4)) | — |
| Weights | `xlmr-base-pii-ml-v5.0.zip` (~1 GB) | `xlmr-base-pii-ml-v4.1.zip` |
| Post-processing | punctuation trim on by default (`trim_punct` in `config.json`), see [Post-processing](#post-processing-punctuation-trim) | none |
| Speed | same architecture and tokenizer as v4.1 (0.87 s GPU / 19.8 s CPU per 100k characters, measured for v4.1; not re-measured) | |

## Why v5

v4.1 scored 0.94 F1 on public multilingual data, but users found it missed PII whenever a sentence
was phrased differently from its training data. Three examples:
- account numbers after "account -", "account:", in lists or brackets, or in real bank / broker formats
- company names and tickers
- English mixed with another language in one sentence

A new test of unseen structures confirmed it: **v4.1 scored 0.557** there. Most account numbers were
found but labelled TIN, and a quarter of look-alikes (amounts, dates, references, postcodes, SWIFT
codes, ISINs) were tagged as PII.

Ma et al. (EMNLP 2023, *Towards Building More Robust NER Datasets: An Empirical Study on NER Dataset
Bias from a Dataset Difficulty View*) explain the mechanism: models learn entity strings rather than
their context, and only training examples whose **context** decides the label make them robust.
v5 changes the training data accordingly, and nothing else.

## Results

**Strict F1:** exact character boundaries and the right label. **Lenient F1:** the right label and
any overlap with the gold span. **Bold** = the better model on that row. v5.0 and v4.1 use the
identical recipe, so the differences come from the training data, from the matching validation set
used for checkpoint selection (`ml_val_v5`: the same documents with merged addresses), and from the
v5.0 punctuation trim (see [Post-processing](#post-processing-punctuation-trim)).

### Post-processing: punctuation trim

v5.0's predictor trims punctuation that the tokenizer glues onto an entity:
- an unmatched closing bracket (`2317299980)` → `2317299980`)
- a leading list comma or colon (`、5819224667` → `5819224667`)
- a final `.` / `。` after a number (`607009209.` → `607009209`)
- one pair of brackets around a whole span (`(陈伟明)` → `陈伟明`)

`Pte. Ltd.`, initials (`S. Lee`) and brackets inside a name (`A (Holdings) Ltd`) are kept.

It is switched on by `"trim_punct": true` in the released `config.json` ([`predict.trim_span`](../src/predict.py)). Models without that key, including every v4 model, behave as before. It moves span edges only, so lenient F1 is unchanged. The issue was found by analysing errors on `ml_struct_test`, so the dev sets are the primary evidence:

| v5.0 strict F1 | without trim | **with trim (released)** |
|---|---|---|
| `ml_struct_dev` | 0.876 | **0.921** |
| `ml_wm_dev` | 0.914 | **0.934** |
| `ml_synth` | 0.936 | **0.960** |
| `ml_real` / `ml_mixed` (merged) | 0.942 / 0.932 | **0.973 / 0.974** |
| English test (original / merged) | 0.894 / 0.908 | **0.911 / 0.925** |
| English stress | 0.963 | 0.962 |
| `ml_struct_test` / `ml_wm_test` | 0.873 / 0.939 | **0.948 / 0.949** |
| Kiii² | **0.857** | 0.851 |

Kiii² is the exception. Its gold spans include the surrounding brackets and full stops
(`(6304679091)`, `010-7930-0230.`, `[010-4895-0219]`), unlike every other source and the project's
label definition. Trimming fixes 468 Kiii² spans and "breaks" 564 that only matched because of that
convention (PHONE 0.925 → 0.861 strict). To reproduce Kiii²-style spans, pass
`PIIPredictor(..., trim_punct=False)`.

## What changed from v4

v5.0 = v4.1's model and recipe trained on new data. Changes to the training data:

1. **Sentence frames (25% of training documents, 113,077 documents).**
   - **Hand-written frames:** 821 frames in [`frames/train/`](../frames/train), packed 1–4 per document (56,539 documents):
     - all 12 languages, plus English + X in both directions for the 11 other languages
     - wealth-management workflows: source of wealth, RM notes, KYC checks, EDD, periodic reviews, investment consultation, stock pitches, onboarding, trade instructions
   - **Wealth-management grid documents:** 56,538 documents from [`src/wm_gen.py`](../src/wm_gen.py):
     - every label in every context (field, cue before, cue after, no cue, list, bracket, spoken)
     - every format (markdown table, bullets, numbering, lines, prose, call transcript)
     - every language setting
   - **Matched contrasts:** the same frame shapes carry look-alikes that must stay unlabelled (amounts, dates, references, postcodes, SWIFT codes, ISINs), using account-length numbers, so only the context decides.
2. **Real account formats.** [`configs/account_formats.yaml`](../configs/account_formats.yaml): 88 institutions in 18 jurisdictions (banks, private banks, custodians, brokers including IBKR, Pershing, BNY, Schwab, Fidelity, Phillip, CDP, NSDL / CDSL), each format with a cited public source. 56 are verified, 27 partial (sampled less often), and 5 unverified (never used). An account and the bank named next to it share an institution.
3. **Merged address fragments.** 22,713 AI4Privacy addresses labelled as separate street / number / postcode spans are joined into one span ([`src/address_merge.py`](../src/address_merge.py)). 25,151 lone postcode fragments are excluded from the loss: their surrounding address is often unlabelled in the source. The rule "a standalone postcode is not PII" is taught by the frames instead.
4. **Real values.**
   - **Names:** from the real-name NER corpora, filtered by script. Vietnamese names must consist of valid Vietnamese syllables.
   - **Dates:** each language's own formats (Buddhist era, 民國, Japanese eras, Arabic / Devanagari digits). DOB and ordinary dates share formats, so only the context separates them.
   - **Bilingual aliases:** a native name and its real romanisation (pinyin and Hokkien / Teochew / Cantonese surnames, Hepburn, Revised Romanization).
   - **Tickers:** 57 listed companies in 14 markets with their correct exchanges, labelled BUSINESS.

Unchanged: the public sources, the 8 labels, the tokenization settings (`script_boundaries`,
visible line breaks), the model, the learning rate, the epochs and the batch size.

## Training methodology

**One factor at a time.** v5.0 differs from v4.1 only in the training data. Further v5 models
(language adapters, head-only, partial unfreezing, financial pre-training) are trained separately
on the same `ml_train_v5` and will be released as v5.1+.

| | v5.0 |
|---|---|
| Start | `xlm-roberta-base` |
| Trained | all parameters |
| Learning rate / epochs / batch / window | 2e-5 / 3 / 32 / 384 tokens (stride 96), as v4.1 |
| Steps / time | 46,206 / 1 h 43 min on an RTX 5060 Ti (bf16) |
| Checkpoint selection | macro-average F1 over the 12 languages of `ml_val_v5` |
| Best validation macro-F1 | 0.9445 (not comparable with v4's `ml_val` numbers: merged addresses) |
| Seed | 42 (single run) |

**How the frame share was chosen.** The frame share (25%) is the only setting that was tuned. A pilot
trained v4.1's recipe on four 50,000-document sets with 0 / 10 / 25 / 40% frames, scored on the dev
sets. The selection rule was fixed before the results: the highest mean of `ml_struct_dev` and
`ml_wm_dev` among shares whose `ml_real` is within 0.010 of the 0% run.

| Frame share | `ml_real` | `ml_struct_dev` | `ml_wm_dev` | Rule score |
|---|---|---|---|---|
| 0% | 0.867 | 0.571 | 0.770 | 0.670 |
| 10% | 0.858 | 0.867 | 0.897 | 0.882 |
| **25% (chosen)** | 0.860 | 0.885 | 0.916 | 0.900 |
| 40% | 0.851 (outside 0.010) | 0.899 | 0.917 | 0.908 |

**Entity-vs-context difficulty (the paper's measure, [`src/difficulty.py`](../src/difficulty.py)).**
For each span, two classifiers predict the label: one from the span text alone, one from its context
with the span masked. CEIM = how much more the span text tells than the context. Share of
"context decides" spans (low CEIM), 107k spans, first frame set at 15%:

| Data | All spans | ACCOUNT | TIN | DOB | Look-alikes |
|---|---|---|---|---|---|
| v4 `ml_train` | 7.6% | 10.8% | 11.2% | 0.9% | 9.8% |
| `ml_train_v5` (first frame set) | 9.3% | 25.5% | 22.7% | 3.3% | 11.6% |

**Test discipline.**
- Dev sets (`ml_struct_dev`, `ml_wm_dev`) were used for choices.
- The test sets (`ml_struct_test`, `ml_wm_test`) were first run once for v5.0, then once more after the punctuation trim, which came from analysing `ml_struct_test` errors. The trim's effect is therefore judged on the dev sets (Post-processing table).
- Dev and test frames use cue words, context patterns and document shapes that training never saw (every spec list is split three ways). Their values come from test-only pools.
- Test scores closely match dev scores (with trim: 0.948 vs 0.921; 0.949 vs 0.934).

## Usage

```python
from predict import PIIPredictor           # run from src/
p = PIIPredictor("../outputs/xlmr-base-pii-ml-v5.0")
p.predict("Hi Tan Wei Ming (陈伟明), 已经 transfer SGD 25,000 到 account 123-456789-001, ref TT240918。")
# -> PERSON 'Tan Wei Ming', PERSON '陈伟明', ACCOUNT '123-456789-001'
#    (the amount and the reference stay unlabelled)
```

Same interface as v4.1. `script_boundaries`, visible line breaks and `trim_punct` are read from the model
config; `PIIPredictor(..., trim_punct=False)` returns the untrimmed spans.

## Limitations

- **Account formats with letters.** These are tested only on formats seen in training (`ml_wm_known`), with 16–133 examples per family. Truly unseen letter-prefixed formats are not tested.
- **Kiii²-style spans.** With the trim on, gold that includes surrounding brackets or full stops scores lower strict F1 (Kiii² 0.857 → 0.851).
- **Remaining weak spots** (`ml_wm_test` strict recall):
  - addresses in call transcripts
  - company, account and tax numbers in narrative sentences with no cue (accounts 0.84)
  - unusual address structures in `ml_struct_test` (0.65)
- **Languages:** Japanese, Korean and Malay are the lowest languages on `ml_wm_test` (0.86–0.90).
- **Address definition.** v5 labels whole addresses. On AI4Privacy-style fragment gold, its ADDRESS score is lower than v4.1's (`ml_real` overall 0.907 vs 0.942), and a standalone postcode is no longer tagged.
- **Synthetic evaluation.** `ml_struct_*` and `ml_wm_*` are generated by this project's own frames. Different phrasings and values from training, but the same authoring. Only Kiii² is real data, and there v5.0 is level with v4.1 (lenient 0.995 vs 0.996). Real wealth-management documents would be the strongest confirmation.
- **Single seed.** Between two pilot runs that differed only in which 50,000 public documents were sampled, `ml_struct_dev` moved by 0.085 at 0% frames. Differences of a few points on the structure sets are within noise.
- **English test vs v3.0:** 0.911 (original gold) and 0.925 (merged gold) vs v3.0's 0.925 (original gold). v3.0 remains a strong English-only option.

## Reproduce

```bash
cd src
python build_ml_train.py --v5            # ml_train_v5 / ml_val_v5 (frames.share in configs/ml_sources.yaml)
python frames.py --export_struct dev --n 12   # ml_struct_dev (and: test)
python wm_gen.py --split dev --min_cell 50    # ml_wm_dev (and: --split test)
python train.py --config train_ml.yaml --train_split ml_train_v5 --val_split ml_val_v5 \
                --output_dir outputs/xlmr-base-pii-ml-A-v5data
python eval_multilingual.py --split ml_wm_test --model_dir ../outputs/xlmr-base-pii-ml-A-v5data --group format --out ../results/A-v5data_ml_wm_test
python eval_wm.py --split ml_wm_test --pred ../outputs/A-v5data_ml_wm_test_predictions.jsonl --out ../results/A-v5data_ml_wm_test_grid
python wm_gen.py --split test --min_cell 30 --known_formats   # ml_wm_known
python release_tables.py --models A A-v5data A-v5data+trim --out ../results/v5_release_tables
# release folder: the trained model + "trim_punct": true in config.json
```

Pipelines: `run_v5_pilot2.sh` (frame-share pilot), `run_v5_queue.sh` (v5.0 and the adapter models),
`run_v5_stage2.sh` (learning-rate sweep and the remaining grid models).

Raw results: `results/A-v5data_*`, `results/pilot2_*`, `results/v5_release_tables.json`,
`results/difficulty_*`.

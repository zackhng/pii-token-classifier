# deberta-v3-xsmall-pii — v2

BIO token classifier for personally identifiable information (PII) in English text. Same 8 labels
as v1. v2 is trained to **reject look-alikes**: ordinary dates vs dates of birth, amounts / currencies
/ bank codes vs account numbers, and companies vs people.

|---|---|
| Version | v2 |
| Weights | `outputs/deberta-v3-xsmall-pii-v2/` |
| Base model | [`microsoft/deberta-v3-xsmall`](https://huggingface.co/microsoft/deberta-v3-xsmall) (~70M params incl. embeddings), fine-tuned **from the original pretrained weights** (not from v1). No domain-adaptive pretraining. |
| Language | English only |

## Labels

8 entity types, BIO-tagged → 17 labels (`O` + `B-`/`I-` per entity), unchanged from v1:
`PERSON`, `BUSINESS`, `ADDRESS`, `DOB`, `ACCOUNT`, `PHONE`, `EMAIL`, `TIN`.

## What changed from v1

1. **Label-map fixes.** Gretel `last_name` → PERSON; Nemotron `tax_id` → TIN and `credit_debit_card` →
   ACCOUNT (all three were trained as `O` in v1).
2. **Look-alikes as hard negatives (`O`).** PIN, CVV, SWIFT/BIC and bank routing numbers stay `O`, so the
   model learns they are not account numbers. Only genuinely ambiguous IDs are masked (`IGNORE`):
   national ID, fax, ID card and passport numbers.
3. **Ordinary dates vs DOB.** AI4Privacy `DATE` (masked in v1) now becomes DOB when a birth cue
   (birth / born / DOB / D.O.B.) directly precedes it on the same line, otherwise `O`.
   DOB placeholders without digits (`[Redacted]`, `MM/DD/YYYY`) are masked.
4. **More DOB data.** Every remaining Nemotron/Gretel train doc with a date of birth is added
   (`dob_boost`): +9,528 Nemotron, +514 Gretel docs.
5. **Date and cue augmentation (train only).** In 50% of docs, birth dates *and* ordinary dates are
   re-written in the same random format mix (25 formats incl. `22/05/1987`, `22.05.1987`,
   `22 May 1987`, `May 22, 1987`, `22-May-1987`, `22-05-87`, `05/87`, `May-87`); in 50% of docs the
   birth cue is varied (`DOB`, `D.O.B.`, `Birth Date`, `Birthdate`, …). Format is no longer a shortcut
   for DOB.
6. **6,000 form-style records** (`src/snippets.py`): key–value lines, tables and single sentences that
   mix targets with look-alikes, e.g. account number next to balance / CVV / SWIFT / card expiry,
   DOB next to transaction and expiry dates, person next to bank or employer.
7. **Leakage guard.** Train docs whose text equals a val/test doc are dropped (5 dropped).

### Label mapping (v2)
Unlisted → `O`; `IGNORE` → masked from the loss; `DATE_CUE` → DOB if a birth cue precedes it, else `O`.
Full map: `configs/label_map.yaml`.

| Entity | Nemotron | Gretel | AI4Privacy |
|---|---|---|---|
| PERSON | first_name, last_name | name, first_name, **last_name** | GIVENNAME, SURNAME |
| BUSINESS | company_name | company | – |
| ADDRESS | street_address, city, state, county, country, postcode, coordinate | street_address | STREET, BUILDINGNUM, CITY, ZIPCODE |
| DOB | date_of_birth | date_of_birth | **DATE (with birth cue)** |
| ACCOUNT | account_number, customer_id, health_plan_beneficiary_number, **credit_debit_card** | bban, iban, credit_card_number, customer_id | CREDITCARDNUMBER |
| PHONE | phone_number | phone_number | TELEPHONENUM |
| EMAIL | email | email | EMAIL |
| TIN | ssn, **tax_id** | ssn | TAXNUM, SOCIALNUM |
| IGNORE | national_id, fax_number | – | IDCARDNUM, PASSPORTNUM |
| `O` on purpose | pin, cvv, swift_bic, bank_routing_number, date | account_pin, credit_card_security_code, swift_bic_code, bank_routing_number, date | DATE (no birth cue) |

overlap) → ~2,432 steps per epoch, ~7,296 steps in total.

Train spans per entity: PERSON 71,905 · ADDRESS 49,182 · BUSINESS 40,739 · EMAIL 30,024 ·
ACCOUNT 21,641 · DOB 19,985 · PHONE 19,292 · TIN 11,634.

Look-alike negatives recorded for evaluation (`data/processed/negatives.jsonl`): test + stress
ordinary dates 7,664, codes 1,567, amounts 892 (amounts only in stress until pfi-400k is added).

| Max sequence length | 384 tokens; sliding windows with 96-token overlap |
| Label all sub-tokens | No (first sub-token labelling, continuation = -100) |

| Batch size | 32 train / 64 eval, gradient accumulation 1 |

test is still a labelled set of real documents. Remaining stress weak spots: codes → ADDRESS /
TIN (5%), TIN precision 0.72 (other numbers tagged as TIN), ADDRESS 0.81.

## Limitations

- **Cannot see line breaks or tabs.** DeBERTa-v3's tokenizer turns `\n` and `\t` into ordinary
  spaces, so `456 Ocean Way⏎Liverpool` and `Dhahran⏎Remitting Bank` look like one line. Result:
  multi-line addresses are missed or cut short, and spans run into the next form field. Being
  addressed in the next version (v2.1).
- **ADDRESS is the weakest entity after BUSINESS** (test F1 0.913, stress 0.809). Error analysis
  (1,200 test docs + 1,000 stress records): ~90–94% exact on test; the rest is line-break
  failures, inconsistent source labels (Gretel labels only the street part and leaves merchant /
  office addresses unlabelled; Nemotron labels bare place names like "France" or "Thai"), and very
  few Asian-format addresses (42 Singapore-style of 49k). Being addressed in v2.1.
- Still only synthetic training data; not yet measured on real documents.
- No amount / currency negatives from real-style documents until pfi-400k is added.
- Few Asian formats: TIN is 41% US SSN; Indian PAN, Malaysian IC and Indonesian NPWP are almost
  absent; Pte Ltd / Sdn Bhd / PT company names and SG-style addresses are rare.
- English only.

# deberta-v3-xsmall-pii — v3

BIO token classifier for PII in English text, for a **wealth management** setting (compliance,
investment, portfolio, risk, relationship managers; Singapore, India, UAE, UK, ASEAN, Asia).
v3 = **domain-adaptive pretraining (DAPT)** of the base model on ~178M tokens of public financial,
regulatory and business-communication text, **then exactly v2.1's fine-tuning** (same data, labels,
configuration). v3 − v2.1 therefore isolates the effect of DAPT.

## Stage 1 — Domain-adaptive pretraining

### Method (`src/pretrain_rtd.py`)
Continues DeBERTa-v3's own pre-training objective, **replaced-token detection (RTD)**, following
Microsoft's reference implementation (`DeBERTa/apps/tasks/rtd_task.py`):
- **Generator**: the released `pytorch_model.generator.bin` (6 layers, hidden 384) does masked-LM on
  15% of tokens (80% `[MASK]` / 10% random / 10% kept); its top-1 prediction replaces each masked
  token.
- **Discriminator**: the 12-layer model we fine-tune, with the released RTD head
  (`mask_predictions.*`: LayerNorm([CLS] + h) → dense → GELU → classifier), predicts for every token
  whether it was replaced.
- **Gradient-disentangled embedding sharing (GDES)**: discriminator word embeddings =
  stop-gradient(generator embeddings) + Δ. Δ is initialised so that step 0 reproduces the released
  model exactly; we verified the released checkpoint satisfies `weight = generator + _weight` (its
  own GDES delta) up to fp16 rounding.
- Loss = MLM + 10 × RTD (the reference default `rtd_lambda`).
- Same tokenizer / vocabulary; line breaks and tabs shown as `▁¶` / `▁|` markers, as in v2.1.

### Pretraining corpus (`src/build_pretrain_corpus.py`, public data only)

Documents cleaned, de-duplicated, long documents split at paragraph breaks (≤ 20k chars), sampled
to a token budget per domain, **shuffled across domains** (every slice of the stream has the same
mix), and packed into 512-token sequences. 1% of documents per domain are held out. Validation and
test texts of the fine-tuning task are excluded.

### Pretraining configuration (`configs/pretrain.yaml`)

| Setting | Value |
|---|---|
| Sequence length | 512 |
| Batch | 8 sequences × 16 gradient-accumulation steps = 128 sequences = 65,536 tokens / step |
| Steps | 2,720 (one pass over 178.3M tokens) |
| Optimizer | AdamW (β 0.9 / 0.98, ε 1e-6), lr 5e-5 (reference RTD script), weight decay 0.01, warmup 5%, linear decay to 0 |
| Precision | fp32 weights + bf16 autocast |
| Checkpoints | every 50M tokens (+ final): discriminator in HF format + generator / head / optimizer state for resume |
| Seed | 42 |

### Pretraining run

- 2,720 optimizer steps, 178.3M tokens, ~21k tokens/s on the RTX 5060 Ti (≈2.4 h of compute).
- Tokens seen per domain: task 46.9M · regulation Asia/UK/UAE/EU 23.6M · regulation US 19.8M ·
  investment / risk 49.5M · communication 37.7M.
- **Interruption:** the first run was stopped by a 2-hour job limit at step ~2,270 (just before the
  150M checkpoint) and resumed from the 100M checkpoint (step 1,526) with its optimizer, scheduler
  and RNG state. Data order and learning-rate schedule are identical to an uninterrupted run; the
  random masking draws after the resume differ (re-seeded), so it is statistically, not bit-for-bit,
  equivalent. Logs: `outputs/dapt_v3_part1.log`, `outputs/dapt_v3.log`.
- Memory: the generator's vocabulary logits are computed only at the ~15% masked positions (same
  loss as the full MLM head); computing them for all 512 positions overflowed 16 GB and ran at a
  third of the speed.

## Stage 2 — Fine-tuning

Exactly v2.1 (see `model_card/v2.1.md`): same 74,036 training documents (incl. 8,000 real-address
records), same validation / test / stress sets, same labels and hyperparameters
(lr 5e-5, 3 epochs, batch 32, max length 384 / overlap 96, `visible_breaks: true`, seed 42).
Only the starting weights differ:
`python train.py --model_name outputs/dapt-v3/tokens-178M --output_dir outputs/deberta-v3-xsmall-pii-v3`.

### What DAPT did

- **Same overall accuracy on the in-distribution test set** (0.925 both): the synthetic test
  documents are what v2.1 already models well.
- **Better on the harder, unseen-layout stress set** (+1.5 F1), mostly from **addresses**
  (+5.6 F1; multi-line exact +10.8 points, India +19 points) and **phones** (+7.2 F1).
- **Costs**: more codes (branch / routing / SWIFT-like numbers) read as ADDRESS or TIN, TIN precision
  on stress 0.83 → 0.76, BUSINESS on test −1.2 F1.
- Net: a modest, mixed gain concentrated in address formats — in line with the 0–2 F1 typically
  reported for domain-adaptive pretraining on entity extraction with a small model. Its real value
  should be judged on real wealth-management documents, which these synthetic sets do not contain.

## Limitations

- Same regression as v2.1 on a bare `A/C` cue in very short inputs (`A/C 0123-456789-0` → clipped or
  missed); `Account No: …` and sentence contexts are fine.
- More look-alike codes tagged as ADDRESS / TIN than v2.1.
- Pretraining corpus is US-heavy for investment text (EDGAR) and lacks MAS / SFC / HKMA regulation
  (no public dataset; sites block automated download).
- Still only synthetic PII documents plus real addresses in templates; not measured on real documents.
- English only.
